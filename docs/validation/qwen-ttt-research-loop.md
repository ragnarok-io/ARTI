# Qwen TTT Recall Research Loop

This is the successor plan for the retired opposite-history diagnostic. It is
a private research protocol and is not part of the public ARTI release.

The claim under test is deliberately narrow:

```text
S_t = Updater(S_(t-1), history_message_t)
student(latest_message, S_t) ~= frozen_teacher(full_history, latest_message)
```

Qwen, the Recall Query, and the initial Bank are frozen. Only the Updater is
trainable. The Bank is the only persistent state; the student read path must
not receive KV cache, an earlier token, an assistant answer, or a hidden copy
of the history.

## Gate 0: contract and reachability

Gate 0 does not train the Updater. It verifies that a counterfactual pair has:

- byte-identical latest `input_ids`, `attention_mask`, `position_ids`, and,
  when materialized, embedding tensors;
- a canonical local position frame for the student latest message, independent
  of the number of history tokens written into the Bank;
- an explicit teacher-frame position ablation, with a manifest-locked absolute
  position hash, so RoPE frame mismatch is measured rather than silently
  conflated with Updater failure;
- equal active history lengths, padded shapes, and role/template budgets;
- a fixed local position frame for the student latest message;
- teacher answers that actually differ because of the history;
- a frozen Qwen and fixed Query whose parameter hashes do not change;
- a zero Bank that is byte-identically zero after reset.

The free-Bank reachability probe then perturbs Bank values directly and measures
the least-squares projection of the teacher historical logit difference onto
the Bank-to-logits Jacobian. If the target direction is not reachable at the
chosen insertion site, Updater training is not an informative test.

The first diagnostic run is deliberately treated as weak evidence. The Bank
has 98,304 values while the probe observes only 64 logits; the Jacobian is
full row rank and both the teacher target and a random target can be fit
in-sample with R2=1. The same output-coordinate holdout gives target R2 values
of 0.478 and -56.52, versus random-target R2 values of -0.717 and -1.739.
Therefore Gate 0 currently establishes local numerical influence, with only a
weak and unstable target-specific projection signal. It does not establish
history storage, updater learning, or behavioral equivalence.

The default student frame is canonical local positions. The runner also accepts
\`--position-frame teacher\`; this maps the exact latest-message suffix into the
absolute positions used by the full-context teacher. Both modes require the
same latest token and mask hashes, and each mode has a separate position hash
in the manifest. This is a controlled diagnostic, not an extra student input.

The non-training asset preflight is:

```bash
uv run --extra qwen python benchmarks/probe_qwen_ttt_reachability.py --plan-only
```

The model-backed probe is allowed only after the hashes and local model are
verified. It produces a report and does not write weights.

Gate 1 consumes the hash-bound manifest generated by
`benchmarks/build_qwen_ttt_counterfactual_manifest.py`. The current v5
fixture is a short preflight asset containing 16 disjoint pairs, split into 8
training and 8 held-out pairs. It is useful for checking the runner, loss
plumbing, checkpointing, and qualitative signal, but it is not large enough
to serve as the final generalization gate. A later locked fixture must use at
least 16 training and 16 held-out pairs with disjoint episode families before
any mechanism claim is made. Every pair shares the same latest
token/mask/local-position tensors and has different target answer tokens. The
manifest is an ignored local research artifact, so its SHA-256 is locked in
the private protocol rather than treated as a public release file.

The next causal fixture uses the explicit `binding-swap` plan family. Each
pair carries one `pair_id`; the two histories have identical token multisets,
active length, role budget, and latest query, while only the key/value order
changes. The manifest records a history-token-multiset hash and refuses an
explicit pair whose histories do not match it. This is the required
same-vocabulary counterfactual; ordinary natural pairs remain useful for
training but cannot substitute for this control.

## Gate 1: sufficient small-task learning

Use a tiny counterfactual task with fixed latest query and randomly permuted
history bindings. Train until a validation criterion or a genuine plateau,
not for a fixed wall-clock duration. The v5 8/8 fixture is only a runner
preflight; the actual train-overfit gate should use at least 16 training
episodes and an independent held-out split:

- at least 16 independent training history/query pairs with disjoint held-out pairs;
- same-length histories and equal answer token budgets;
- disjoint identity/value symbols in the later validation split;
- correct, matched-wrong, and zero Bank branches in the same batch;
- first-token KL as the frequent training signal;
- full-context teacher response logits as targets for a student autoregressive
  rollout whose next input token is always the student's own detached output;
- free-running generation only as validation, never as a hidden training input.

The loss is:

```text
L = L_first_token_KL
  + lambda_response * L_self_generated_response_KL
  + lambda_rank * relu(margin + D(correct, teacher)
                         - D(wrong, teacher))
  + lambda_diff * (
        1 - cos(center(student_delta), center(teacher_delta))
        + 0.25 * relative_delta_error(student_delta, teacher_delta)
    )
  + lambda_partition * (
        D(token_write, message_write)
        + D(random_chunk_write, message_write)
    )
  + lambda_stability * ||delta_bank||^2
```

The historical-delta term uses the union of the teacher's top-128 coordinates
for the two rows of each pair, then applies cosine direction and relative
energy error. The full-vocabulary version is retained as an audit metric and
the full response KL remains part of the training objective. This follows the
existing paired Recall training loss: a 150k-token vocabulary is too large for
raw vocabulary-wide MSE to be a useful causal signal. The rank term is also
only an optimization signal: all branches must use matched tensors and final
validation must include swapped Bank states.

Before training, both the training and validation splits must pass a teacher
identifiability preflight: the target answer must beat its paired
counterfactual answer in logit margin on at least 90% of rows, and the
teacher's top-1 token must differ across at least half of the pairs. Absolute
target-token top-1 accuracy is reported but is not required; the controlled
criterion is the relative history margin.

During training, the opposite-history Bank is differentiable as well as the
correct-history Bank. Otherwise the historical-delta loss can move only one
side of the pair and the model may learn an absolute answer shortcut instead
of a state transition. A detached opposite-history branch is retained only as
an explicit ablation (`--detach-wrong-state`), never as the default protocol.

The teacher may use the full-context response prefix to produce target logits.
The student may not.  The student response branch starts from the latest user
message and feeds back only its own detached generated token at each step.
Teacher-forced continuation is retained only as a diagnostic and is never
used as evidence for the latest-only read contract.

For the causal difference term, the default weight is `0.2`, matching the
existing paired Recall training loss rather than the earlier ineffective
`0.05` setting. The target is the paired difference
teacher(left_history) - teacher(right_history) and the student term is
student(correct_bank) - student(swapped_history_bank). A zero Bank is a
reset control, not a substitute for the opposite-history teacher. Message,
token, and deterministic random-chunk writes are all compared; the random
chunk boundaries are fixed per validation call so the result is reproducible.
The raw Bank-state consistency metric is an optimization signal; final
acceptance must also compare the resulting latest-only logits.

The runner records the provenance of this writer explicitly. The current
implementation captures one frozen no-Recall forward for the complete history
message and replays the resulting token traces for message, token, and
random-chunk partitions. This is a regression test for partition replay, not
yet proof that an online writer which re-captures each token under the updated
Bank is associative. Gate 0 therefore has two separate checks:

1. `frozen_trace_replay`: partitioning the same captured trace stream gives
   the same state and readout;
2. `online_recapture`: each token/chunk is captured after the preceding state
   update, and the resulting message/token/chunk readouts agree.

The second check must pass before token/chunk consistency can be interpreted
as a property of the deployed recursive writer. Reports and checkpoints must
include `history_trace_source` and `history_write_semantics`, together with
every loss weight and response schedule parameter, so a result cannot be
resumed under a different training contract silently.

The strict online path is opt-in and is recorded separately:

```text
--online-consistency-start-step 1
--online-chunk-weight 0.05
```

With this option, each message, token, or random chunk is forwarded again
under the Bank produced by all preceding segments before its trace is written.
The resulting `online_chunk_loss` is a symmetric KL between the latest-only
logits produced by message, token, and random-chunk states;
`online_state_chunk_loss` is retained as a diagnostic. The existing
`chunk_loss` remains the frozen-trace replay metric. A run with only
`chunk_loss` has not demonstrated online recursive capture.

Use the private watchdog for any resource-bounded run:

```text
uv run python benchmarks/run_qwen_ttt_gate1_watchdog.py --max-total-seconds 540 --train-max-seconds 240 -- --protocol <locked-protocol> --output-dir <run-dir> --online-consistency-start-step 1
```

The watchdog covers loading, preflight, training, checkpoint writes, and the
fresh-process evaluator. It writes an immutable envelope and separate stdout
and stderr logs. A timeout is `hard_timeout`, never a convergence result.
Fresh evaluation also compares every numeric metric available in the training
process with the fresh-process result and records `fresh_reload_parity`;
without that comparison, reload is only a load smoke.

The main behavior path is selected independently with
`--history-write-mode online`. In that mode, `correct` and `wrong` Bank states
used by the answer and historical-delta losses are both produced by online
recapture; the replay state cannot satisfy the behavior gate. The default
`replay` mode remains available only for comparing against the earlier v5/v6
diagnostics. A strict TTT result must report
`history_write_mode=online`.

Gate 1 records two separate sub-gates. The consistency sub-gate is active from
the first optimizer step so the writer cannot first memorize whole-message
templates and only later be asked to become compositional. The behavior
sub-gate requires three consecutive *active response updates* with the answer
flip, selected historical delta, and self-generated response criteria. A step
that skips the scheduled response rollout cannot advance that counter. This
separation is necessary: a writer can learn history-conditioned behavior while
still having a poor token/chunk transition, or the reverse. Neither result is
silently substituted for the other.

The held-out Gate 1 criterion passes only when the train set is genuinely
solved, the correct Bank beats matched wrong/reset branches, swapping Banks
reverses the controlled answer, correct response KL is lower than the reset
response KL on validation, token/chunk writes agree, and a fresh reload
reproduces the result. The preregistered causal thresholds are a 0.1 minimum
correct-vs-wrong and correct-vs-reset distance gap, 0.9 answer-flip rate,
historical-delta cosine at least 0.8, relative historical-delta error at most
1.0, chunk loss below 1.0, and three consecutive qualifying validation
windows. The fresh-process result must also have a numeric parity pass against
the saved in-process evaluation; a loadable artifact alone is insufficient.
Before the consistency stage, the report may mark the behavior sub-gate
independently, but the complete Gate 1 cannot pass. This prevents a short run
with an unfinished consistency stage or a non-reproducible reload from being
mistaken for a converged TTT result.

Response supervision has an explicit mode. The default is the free
autoregressive path (`--response-mode rollout`): the latest message is
followed only by the student's own detached generated tokens. This is the only
response path eligible for the latest-only Gate 1 criterion. The
teacher-forced path (`--response-mode teacher`) remains available as an
explicit optimization diagnostic, but its response KL, response ranking, and
token agreement are never evidence for the latest-only claim. An engineering
smoke may disable response work with `--response-mode none` or defer validation
with `--eval-response-start-step`; such a run cannot pass Gate 1 and is recorded
only as a throughput/checkpoint test.

Protocol v8 adds `--response-mode hybrid`: teacher-forced token alignment is
an auxiliary training signal, while the free-rollout branch remains the only
response branch used by the Gate 1 criterion. The auxiliary weight is part of
the protocol and checkpoint contract, so resuming with a different value is a
hard mismatch. Hybrid is a training curriculum, not a relaxation of the
latest-only read contract.

Relative response improvement is not sufficient evidence. The free-rollout
response sub-gate also requires teacher top-1 agreement of at least `0.75` on
the aligned response positions. A student that merely improves over reset while
still disagreeing with the teacher is not a successful answer path.

## Gate 2: controlled generalization

Freeze the architecture, optimizer schedule, and checkpoint selection rule.
Evaluate independently held-out identity/value bindings, combinations, query
templates, order-sensitive episodes, chunk boundaries, and longer histories.
The statistical unit is the independent episode or scenario family, not an
individual answer token. Report each seed, the worst seed, and family-clustered
confidence intervals.

An arbitrary reversed history is not a universal negative. It is used only in
tasks where order changes the correct answer. For order-insensitive facts, it
is a valid equivalent control instead.

## Gate 3: free autoregressive behavior

Only after Gates 0--2 pass, evaluate free-running student answers without a
teacher response prefix. Compare task correctness, teacher-logit KL at the
first answer token, complete response constraint satisfaction, and degradation
across recurrent updates. Teacher-forced alignment remains a training metric,
not the final claim.

## Stopping and asset rules

Training stops at a predeclared criterion: three to five consecutive validation
windows with no material improvement in teacher KL and correct-vs-wrong margin,
after at least one learning-rate reduction and without Bank saturation. A
wall-clock limit is only a safety boundary. If it is reached before plateau,
the result is recorded as `not_converged`, never as mechanism failure.

Every run must save a resumable checkpoint, optimizer state, scheduler/RNG
state, manifest, metrics, and an immutable milestone before moving to a larger
stage. The short preflight is allowed to verify throughput and resume; it is
not allowed to decide whether TTT Recall works.

The recorded online runs completed fresh-process reload with frozen Qwen/runtime
parameters unchanged. Correct-vs-wrong and correct-vs-zero gaps were positive,
and frozen trace partition losses were near machine precision. That is evidence
of a real Bank-induced behavioral signal and a working checkpoint contract. It
is not evidence that the Bank stores a history-general state: the held-out
historical-delta direction remains below the `0.8` gate and the answer flip
rate remains below `0.9`.

The corrected online KV preflight is a separate implementation result. It
keeps the causal `past_key_values` produced by the preceding latest-message
segments while updating the Bank, so token/chunk recapture no longer silently
restarts the transformer from an empty history. The short online training smoke
reproduced its metrics after a fresh reload, but it ran only four optimizer
steps, disabled response supervision, and failed the behavior gate. It must be
used as a regression fixture for the path, not as evidence of TTT usefulness.

The v7 response smoke did execute free rollout and reduced response KL relative
to reset, but its teacher top-1 agreement was only `0.0625`. Under the corrected
criterion this is explicitly a response-gate failure, not a partial success.

The response-branch smoke additionally verifies that rollout now evaluates the
correct and wrong Bank states independently and trains both response ranking and
response historical-difference losses. Before this fix those metrics were zero
placeholders in free-rollout mode, so earlier response numbers are not valid
evidence for a correct-vs-wrong response claim.

The v6 fixture intentionally uses 12/12 pairs because seven of the original
32 generated pair ids had identical answer tokens on both sides and were
invalid counterfactuals. The next fixture must add answer-distinct pairs or
change the task construction; invalid pairs must not be used to reach a target
sample count. The next training run should therefore change one declared
factor in the data/protocol or writer semantics, not merely continue either
 checkpoint.

## Next locked loop: protocol v8

The next run uses
`benchmarks/qwen_ttt_binding_swap_research_loop_protocol_v8.json`. It keeps the
same frozen Qwen, fixed Query, zero Bank, online recapture, and 12/12 split as
v7, but makes the response curriculum explicit: teacher-forced alignment has
weight `0.5` during training and free rollout is still the sole response gate.
The run is accepted only when the existing behavior, consistency, response,
and fresh-reload gates pass in three consecutive validation windows. A short
watchdog run may measure throughput, gradients, checkpoint recovery, and
numerical stability; it must be recorded as `not_converged` unless the curve
reaches the declared gates. No larger Bank, extra sites, or longer training
stage is authorized before this loop passes.
